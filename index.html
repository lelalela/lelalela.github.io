Engineering Deep-Dive & Troubleshooting

실제 운영 환경에서 마주한 기술적 난제와 해결 과정 (Problem → Action → Result)

CASE 01

플래시 세일 선착순 주문 시 동시성 이슈 및 재고 초과 판매 해결

Redis Redisson / Distributed Lock
문제 상황 (Problem)

특가 이벤트 시 단 1초 만에 1,500건 이상의 동시 주문이 인입되며 데이터베이스의 Race Condition으로 인해 재고 100개 상품이 108개 결제되는 오버셀링(Overselling) 사고 발생.

해결 접근법 (Action)

단일 DB 락(Pessimistic Lock)의 DB 커넥션 풀 고갈을 방지하기 위해 Redis Redisson 기반 분산 락 도입. AOP Custom Annotation(`@DistributedLock`)을 구현하여 비즈니스 로직 침투 없이 락 획득/해제 라이프사이클을 트랜잭션 범위와 정교하게 분리.

결과 & 성과 (Result)

재고 초과 결제 0건 달성, 락 획득 타임아웃 설정을 통한 안정적 대기열 제어로 DB CPU 사용률을 90%에서 35%로 안정화.

CASE 02

복잡한 다대다 연관관계 조회 시 JPA N+1 슬로우 쿼리 95% 개선

QueryDSL / Fetch Join / Indexing
문제 상황 (Problem)

주문 목록 조회 시 1회 요청마다 하위 배송지, 주문 상품, 쿠폰 엔티티 조회 쿼리가 루프를 돌며 총 350개 이상의 쿼리가 실행되어 API 응답 시간이 2.8초에 육박함.

해결 접근법 (Action)

QueryDSL을 도입하여 동적 쿼리를 타입 세이프하게 작성하고, 1:N 컬렉션 페이징 시 메모리 OOM 방지를 위해 `default_batch_fetch_size: 500` 설정 적용. 다빈도 검색 조건 컬럼에 복합 인덱스(`(member_id, created_at)`) 생성.

결과 & 성과 (Result)

실행 쿼리 수 350개 → 단 3개로 대폭 감소, API 평균 응답 속도 2.8초 → 140ms로 95% 단축.
